# zarr-spectral-schema (Python binding)

Python binding for the CCAT/CHAI L0–L1 Zarr store contract. Constants and the
validator are *derived* from the spec (`spec/schema.yaml`), shipped here as
package data — there is no hand-typed duplicate of the contract.

```python
import zarr_spectral_schema as zss

zss.DATA_5D  # "data_5d"   — spec-derived constant
zss.L0_SCHEMA_VERSION  # "3"
problems = zss.validate("path/to/store.zarr")  # [] == conformant
problems = zss.validate("s3://bucket/store.zarr")  # needs the `s3` extra
```

`validate` returns the errors only. `check` returns a `ValidationResult` with
`errors`, `warnings` and `ok`.

```python
result = zss.check("path/to/store.zarr")
result.ok  # True when `errors` is empty; warnings do not fail a store
result.errors  # list[str]
result.warnings  # list[str], for example a newer minor version
```

## Contract

The package validates L0 schema version 3 and L1 schema version 2.0.

- The validator accepts the current major version only. A store below `min_supported` gets one version error, without a prefix. Structure findings follow when the store lacks fields of the current version. A consumer stops on the version error.
- A structure finding starts with `[L0] ` or `[L1] `. A version error and a level-detection error have no prefix.
- A scan group is `scan_N/`. A multi-frontend scan holds `band_B/` groups, at L0 and L1.
- Arrays declare `dims` (Zarr `dimension_names`) and `units`. The L1 `flags` array uses the `flag_bits` constants.
- L0 `data_5d` is `uint32` with fill value 4294967295.
- `raw_fits_headers` and `frontend_backends` have dims `[receiver, array, subscan]`.
- `source_l0_store` is a URI reference.

## Object storage

The validator reads a local path or an `s3://` URL. It reads `zarr.json`
objects only and never a chunk.

- The package is not on PyPI. Install it with the `s3` extra from a checkout, `pip install "./bindings/python[s3]"`, or from git: `pip install "zarr-spectral-schema[s3] @ git+https://github.com/ccatobs/zarr-spectral-schema@<sha>#subdirectory=bindings/python"`.
- Set the endpoint and credentials in the standard AWS environment variables: `AWS_ENDPOINT_URL`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_DEFAULT_REGION`. Both bindings read `AWS_DEFAULT_REGION`.
- Without the extra, fsspec cannot open an `s3://` URL.

## Rust binding

The Rust crate in `bindings/rust/` has the same contract and the same findings.
`check(&Path)` and `validate(&Path)` take a local path.

- S3 support sits behind the cargo feature `s3`, off by default. Enable it with `zarr-spectral-schema = { ..., features = ["s3"] }`.
- Pass the URL to `check_url("s3://bucket/store.zarr")`, or as `Path::new("s3://bucket/store.zarr")`.
- The S3 check reads the same `AWS_*` environment variables and blocks on its own tokio runtime, on a thread of its own. A caller inside a tokio runtime may call it.
- An `http://` endpoint, such as a local test server, also needs `AWS_ALLOW_HTTP=true`.

The synced `spec/` directory under the package is generated by `make sync` at the
repo root; do not hand-edit it. See the repo README and `docs/adr/0007-…` for the
design.
